# 蛋岛桌面宠物

从 [eggislandgame.xyz](https://eggislandgame.xyz) 扒下来的 3D 角色，做成桌面挂件。

Electron + Three.js，透明置顶窗口，悬浮在屏幕角落。

## 角色

| 名字 | 模型 |
|---|---|
| 蛋糕纯 | `character-cake.glb` |
| 珠玉纯 | `character-jade.glb` |
| 小蛋（跟宠） | `pet-egg.glb` |

三个模型都**没有动画 clip**，只有骨骼。动画是用站点自己的 `renderer/animation.js`
（`setupCharacterRig` / `setupPetRig` + `updateRig`）程序化驱动骨骼实现的——
呼吸、悬浮、坐姿、转头全靠每帧算。小蛋是蛋岛原版跟宠模型，82 根骨骼，会自己飘、摇、眨眼。

## 召唤与自动隐藏

**启动后就安安静静待在右下角，不会自己消失。** 之前那版「开完机 3 秒无条件隐身」是错的：
人还在桌面、什么软件都没点进去，她也会突然不见。现在改成：

- 默认**不自动隐藏**；人在桌面待着就一直露着。
- 想要老行为，去托盘勾 **「切到别的软件时自动隐藏」**。开启后也只在真的失焦切走时才收起，
  而且刚启动 8 秒内不触发、鼠标还停在她身上不触发、被你点过 / 召唤过就整轮不触发。
- **Ctrl + Alt + E** 或点托盘图标：召唤 / 收起，随时手动控制。

被召唤出来时会蹦一下、转半圈。所有提醒一律用角色身上的半透明气泡说，不弹系统通知。

## 启动速度与后台占用

便携单文件 `dist/EggIslandPet.exe` 约 183MB，**每次双击都要把整包自解压到临时目录**，
这是「打开超级慢」的真正原因，不是代码慢。想要秒开请用免解压版：

```text
dist\win-unpacked\EggIslandPet.exe     ← 日常用这个，双击直接跑
dist\EggIslandPet.exe                  ← 单文件，方便拷给别人 / 上传，启动会慢
```

`win-unpacked` 整个文件夹要一起留着，别只把 exe 抠出来。两个版本共用同一份设置和歌单。

后台策略（藏起来之后几乎不占资源）：

- 收起时主进程发 `pet-pause`，渲染层 `cancelAnimationFrame` 停掉整个主循环，
  清空所有 CSS 特效节点，WebGL **一帧都不画**；`document.hidden` 再做一层兜底。
- `backgroundThrottling` 改回 `true`，让 Chromium 正常节流后台页面（之前写死 `false`，
  等于强制桌宠在后台也满帧跑 3D）。
- 静止节目（发呆 / 坐 / 睡）降到 30fps，秋千、转圈、散步、撒花才是 60fps。
- 删掉常驻的 16ms 拖动轮询（只在右键拖动期间存在），置顶兜底从 15s 降到 60s 且隐藏时不执行。
- 关掉组件更新 / 翻译 / 投屏等用不到的 Chromium 后台服务；`three.core.js` 本地存在时
  不再 `await` 任何网络检查，托盘先建好再建窗。

设 `PET_TIMING=1` 启动，会在 `%APPDATA%\EggIslandPet\boot-timing.log` 写各阶段耗时。

## 放音乐

点她就会播放。歌放在：

```
%APPDATA%\EggIslandPet\music
```

右键菜单里有 **「打开音乐文件夹」**，点一下直接打开，把 mp3 / m4a / wav / flac 拖进去就行。
支持多首，按文件名顺序循环，一首放完自动下一首。

**歌要你自己准备**——版权在平台和歌手手里，程序只负责播本地文件。

### 小蛋跟宠

蛋岛原版 `pet-egg.glb`，不是额外画的光球：圆滚滚的 Q 版小蛋，有脸、有小手小脚，
带一圈柔光和拖尾光点，绕着角色飞、轻轻上下摇。按 **F** 或右键菜单可以关掉 / 打开。
它不只是摆设，具体能干什么见下一节。

### 点击反馈

- 单击：飘爱心 / 星星、蹦一下、转个身、冒一句小台词，顺便放歌
- **连击**：越点越夸张，第 3 下起满地开花，第 6 下起换成星星雨 + 「×N 连击」气泡
- 手动转过之后约 1.8 秒会**自动转回正面**

### 花草（走一路开一路）

一株花不是「一个六瓣图标」，而是整套结构：**草叶 → 花茎 → 叶子 → 外层 5 瓣 → 内层 5 瓣 → 花心**，
按 0 / 180 / 420 / 560 / 730 / 1000ms 依次长出来，2.6~3.8 秒后整株淡出。

- 花瓣是椭圆渐变 + 内阴影勾边，两层错开 36°，所以有厚度，不是平面贴纸。
- 颜色随机：白粉 / 奶黄 / 淡紫 / 杏 / 冰蓝 / 樱粉；草有 3 套低饱和配色，不是荧光绿。
- **锚点用相机投影算**（`groundPoint()` 把角色脚底的世界坐标投成屏幕百分比），
  整株落在脚底略偏下，从脚前面长出来——**既看得见，又不会盖住脚**。
- 散步时每一步长一株花 + 70% 概率补一撮纯草；连击庆祝、撒花节目共用同一套。

### 特效

**星尘是 3D 粒子，不是 DOM 圆点**（`renderer/fx3d.js`）。做法照搬蛋岛原站
`atmosphere.js` 里星星 shader 的思路：软核 `exp(-r²·5.2)` + 柔光晕 + 十字星芒，
720 个粒子共用一个 BufferGeometry，位置全部在 shader 里按 `uTime` 算，CPU 每帧只改一个 uniform。
区别是原站给不透明夜空用 `AdditiveBlending`，而这里是透明窗口，加色会把背景糊成灰团，
所以改用 `NormalBlending` + 高光提亮，背景保持全透明。

- 点击 / 连击：从胸口喷一撮星尘；10、20、30、40 连各有一档不同的庆祝
- 走路开花：草叶 → 花茎 → 叶 → 两层花瓣 → 花心，按 1 秒内依次长出来（DOM，因为要真实花瓣形状）
- 追小精灵：横跨窗口跑，身后甩一串星尘
- 荡秋千：身边持续飘柔光和花瓣
- 平时：每 1~2 秒飘 1~2 颗，别让画面死气沉沉

花瓣和花还是 DOM（`#fx` / `#fxBack` 层），因为要的是真实花瓣形状而不是光点。
`prefers-reduced-motion` 下自动降级。

### 手感上的细节（这次补的）

- **注视**：鼠标在屏幕哪边，她就微微转头看过去（头最多 24°，胸口跟三分之一）。拖动她时不抢控制权。
- **跟着歌摇摆**：放歌时用 WebAudio 读低频能量，身体跟着鼓点起伏、轻轻左右晃。没歌就自然停。
- **甩出去**：右键拖着甩一下松手，她会带着惯性滑出去、撞到屏幕边缘弹回来，摩擦停下后记住位置。
  慢慢挪过去的那点速度不算，不会误触发。
- **贴边**：拖动中离边 48px 就亮一条粉色磁吸提示；松手时四条边 70px 内都会吸过去，
  200ms smoothstep 滑到位，不会半截挂在屏幕外。
- **被吸住的表演**：先往窗口里挣 0.65 秒（阻尼振荡），再被拖到边上，说「放我出去…」；
  拖出来说「又见到你了」。探头期间锁住节目轮换，免得随机切到睡觉 / 坐下把脸压出画面。
- **贴边 = 像门框那样探头，但不画门框**：窗口吸在屏幕最外侧那条边上，取景整体平移，
  让**原始大小**的头紧贴屏幕物理边（`zoom` 恒为 1），再用 Three.js 自带的全局裁剪面
  把身体齐着窗口下边界切掉，断面藏在窗口外。屏幕那条黑边本身就是「门框」，
  额外画出来的框沿全部删掉；吸附成功时连拖动提示条也一起撤掉，画面上不留任何假框。
  两只带弯曲手指的小手抬到屏幕边沿，一只搭在边上、一只扶在头侧。
  纯 Three.js 内置能力，**没有新增任何依赖**。
- 踩坑：把镜头推近成 1.75 倍特写虽然头完整，但看起来像「屏幕里一颗大头」，木木要的是**边边**。
  换成 zoom=1 后又发现按特写反推的头位偏低，脸整块落在窗口外只剩帽尖；
  最后加 `__pet.probe()` 把头骨和包围盒投影成窗口像素（实测头骨 worldY 0.733 → 画面 198px）才定准取景。
- **不要地面阴影**：透明窗下那圈椭圆影子怎么调都像一摊墨 / 黑洞，试过 256px 七段渐变后删掉了，
  这个画风本来也不需要影子。
- **时段问候**：早 / 午 / 晚 / 深夜各一句话，同一个时段只说一次，重启也不会重复。

### 它主动做的

## AI 对话

双击角色打开聊天窗（半透明玻璃质感），点右上角 ⚙ 填接口（OpenAI 兼容格式）：

- 本地 Ollama：`http://localhost:11434/v1`，模型填 `ollama list` 里的名字，Key 随便写
- 云端：`https://api.deepseek.com/v1` + 你的 Key + `deepseek-chat`

请求走主进程转发，绕开渲染层 CORS。

### 三种输入方式

| 方式 | 说明 |
|---|---|
| 打字 | Enter 发送，Shift+Enter 换行 |
| 🎤 按住说话 | **微信输入法式**：按住开始、实时上屏、松手就发、上滑取消。见下节 |
| 👁 看屏幕 | 截当前屏幕发给视觉模型 |
| ⬚ 圈一块 | **自由套索**，可以画任意形状。圈完不自动提问——先出现缩略图和「这是什么」按钮，你想问什么就打字或说话 |

### 语音输入（不用 Google、不上传声音）

之前用的 Web Speech API 在 Electron 里要连 Google 服务，国内基本不可用，已彻底换掉：

- **识别引擎**：`sherpa-onnx` 的 **Paraformer 中文模型**（int8，78MB），全程在本机 CPU 跑。
  麦克风采 16k 单声道 PCM，分块送主进程；因为 Paraformer 是非流式的，
  用「每 0.9 秒把已收到的音频整段重解一次」做增量预览，字照样往上冒，松手再精解一次。
- **为什么换掉流式 zipformer**：同一批语料（Edge TTS 合成，接近真人语速）实测，
  流式 zipformer(int8, 174MB) 平均字错率 **25.6%**，而且在长音上会打转——
  「放首歌听听吧」被识别成「放手歌听听听听听吧」。Paraformer 同样 6 句 **0.0%**，
  5 秒音频只要 50ms，体积还小一半。
- **按住说话**：按住 🎤 开始，浮层显示识别中的文字；**上滑取消**、松手发送，跟微信一样。
- **AI 纠错**：识别原文已经比较准，纠错层只负责补标点、改同音字；
  接口慢 / 断网 9 秒后自动跳过，不卡住。
- **聊天和指令都能听懂**：`localIntent()` 用本地关键词规则判断意图，断网也生效，
  AI 在线时再纠一次。聊天直接发给角色；指令直接执行：
  看屏幕 / 开始专注 25 分钟 / 读剪贴板 / 放歌 / 换个节目 / 隐藏 / 翻译。
- **微信输入法的识别引擎是腾讯私有服务，没有公开接口，无法内嵌**（和 WorkBuddy 一样）。
  所以这里用「本地模型 + 大模型纠错 + 本地意图兜底」把听得清、听得懂补回来。

端到端实测（IPC 全链路，渲染层分块送 PCM → 主进程解码 → 纠错 → 意图）：
输入「放首歌听听吧」，识别原文 `放首歌听听吧`，纠错后 `放首歌听听吧。`，判定 `command / music`。

模型不进仓库也不进 git（79MB），首次使用前自己下：

## 实现要点（踩过的坑）

1. `three.module.js` 只是个入口，真正实现在同目录 `three.core.js`，两个都得有。
2. `file://` 下加载 ES module 会失败，报错信息会误导成 CORS——实际是依赖文件没下全。
3. 相机按模型高度自适应，人物和宠物才能都占满画面约 3/4。
4. 窗口用 `setIgnoreMouseEvents(true, { forward: true })` 实现透明区穿透，
   渲染层用 raycast 判定是否悬停在模型上再切回可点击。
5. 透明窗口里 WebGL Sprite 粒子几乎看不见（加色混合 + 窗口 alpha 合成会糊成灰团），
   换成 DOM 覆盖层 + CSS 动画后颜色立刻鲜亮。`capturePage()` 抓不到 CSS 动画层，
   验证特效要用桌面截图。
6. `lastRotateAt` 必须和 `tick()` 一样用 `performance.now()`；之前点击里写了 `Date.now()`，
   两者差 1.7e12 毫秒，自动回正永远不触发。
7. 长按右键拖动时系统偶尔把透明窗口撑大：主进程 `setBounds` 带固定宽高、`resize` 时锁回，
   渲染层再把 `camera.aspect` 钉死为 1，双保险。
8. **骨骼旋转必须绕骨骼自己的局部轴**（`animation.js` 里 `rig.joints.get(bone).x`）。
   之前叠加坐姿 / 手部时直接拿世界 `(1,0,0)` 乘 quaternion，Mixamo 大腿和手臂初始朝向各不相同，
   结果腿被拧成 Z 字、脚尖朝天、手指整排翻起来。同一个 `pitchBone()` helper 同时修好了手和脚。
9. 秋千座板要**对准髋部**（实测 `hipY≈0.472`，坐实后约 0.437，板面 0.445），不是放在脚踝；
   绳子长度、板子 z 位置、人物前移量要一起配，否则人看着是「站」在秋千前面。
10. 透明窗口下 `clip-path` / `filter: drop-shadow` / `mix-blend-mode` 也会被 alpha 合成吃掉，
    和 WebGL Sprite 是同一类坑。星尘只能用 `border-radius` + 实色渐变 + `box-shadow`，
    靠形状和尺寸取胜；半透明色 + 1px 细线在这个环境里等于看不见。
11. **换角色必须原子切换**：先把新 glb 完整加载 + 建好 rig，成功之后才 dispose 旧模型。
    旧写法先删旧的再 `await` 加载，任何一次加载抖动都会让角色整个消失（表现为「另一个角色用不了」）。
    现在失败会保留原角色并弹出气泡说明，成功也会明确说一句「XX 来啦~」，不再点了没反馈。
12. **连击「点不到 / 点着点着停了」是三个原因叠加**：
    ① `tap()` 旧逻辑把 330ms 内第二下点击直接判成双击去 `openChat()`，聊天窗一开宠物窗口被隐藏；
    ② 每点一下都 `jumpVel=2.6 + yawVel=1.3`，角色一跳一转，下次 raycast 打空、鼠标被透明区穿透；
    ③ 每点一下都 `toggleMusic()`，连击时音乐一下开一下关。
    改成：单点零延迟反馈；双击交给原生 `dblclick` 并延后 300ms 确认有没有第 3 下；
    3 下起进入 `comboMode`，期间只压扁不跳、不转身、不切歌、不切节目；
    `hitTest` 加窗口中央椭圆兜底，raycast 打空也算命中。
13. **裙摆只露脚尖**：模型是单个 mesh，改不了裙长；加一层白纱筒会变成难看的「罩子」。
    正解是把坐姿大腿角度从「前伸 -1.32」改成「往后收 +0.30」，腿藏进原有裙摆后面，
    正面只留一点鞋尖。两个角色 hipY 不同（0.419 / 0.472），座板和绳长按角色重算。
14. **sherpa-onnx-node 的 external buffer 坑**：`readWave()` 返回 native external
    Float32Array，Electron 会报 `External buffers are not allowed`。生产链路走 IPC 的普通
    ArrayBuffer 没问题，但仍要再复制一层 `new Float32Array(len); s.set(incoming)`。
    调试脚本别用 `-e`（Node vm 同样禁 external buffer），要用真实主进程；
    `ELECTRON_RUN_AS_NODE=1` 下 require 这个 addon 是能加载的，ABI 兼容。
15. **自动隐藏不能是无条件定时器**：旧版 `ready-to-show` 里挂了个 3 秒 `setTimeout(hide)`，
    跟用户有没有切进软件完全无关，所以「人在桌面它也藏」。`userTouched` 当时定义了却没用上。
    现在所有 `show/hide` 收敛到 `showPet()/hidePet()`，隐藏判定只发生在真实 `blur` 之后，
    且要过「开关 + 启动宽限期 + 鼠标是否悬停 + 是否被召唤过 + 有无聊天/圈选窗」五道闸。
16. **后台吃资源的元凶是 `backgroundThrottling: false`**。隐藏窗口后 rAF 仍满帧跑，
    `updateRig()` 每帧算人物 + 82 骨骼小蛋，DOM 花瓣还在做 CSS 动画。
    修法是显式 `pet-pause` 停循环 + 清特效，而不是指望系统自己节流。
17. **便携 exe 每次启动自解压 183MB 到 `%TEMP%\<随机目录>`**，进程表里能看到 6 个子进程
    全指向临时目录；这是启动慢的主因。真正要秒开就得用 `win-unpacked` 里的 exe。
18. **Three.js 的 `Points` 没有 `position` 属性就一个点都不画**：自定义 shader 只用自定义
    attribute 时很容易忘了这条 —— 渲染器靠 `geometry.attributes.position` 决定绘制数量，
    没有它 `renderer.info.render.points` 恒为 0，而且不报错、不警告，表现就是「代码全对但看不见」。
    另外 `gl_PointSize = size * scale / -mv.z` 这种写法会把 10px 算成 700px，
    整屏糊成一层极淡的灰雾（看起来像「有点脏」而不是「有粒子」），
    点尺寸按像素给、只做轻微远近缩放才对。
19. **「流式」不等于「准」**：一开始想当然选了 streaming zipformer，觉得能边说边出字更高级。
    实测 6 句常见口语平均字错率 25.6%，而且分块大小从 0.1s 改到整段结果完全一样
    （说明不是喂法的问题，是模型本身），还会在长音上循环吐字（「听听听听听」）。
    换成非流式 Paraformer：0.0%、5 秒音频 50ms、体积 174MB → 78MB。
    没有原生流式字幕就用「每 0.9 秒整段重解一次」补，40~120ms 一次完全扛得住。
    **选型要靠量出来的 CER，不要靠名词好听。**
    纯本地应用不该在启动关键路径上 `await` 任何 I/O（`ensureThreeCore` 已改成后台补文件）。
20. **走路开的花像贴纸，是三个错叠在一起**：① 六片正圆花瓣 + 外发光 `box-shadow`，
    十几层叠起来糊成一团光斑；② 花写在 60~86% 高度，正好压在脚和小腿上；
    ③ 位置是写死的百分比，相机高度 / 窗口 DPI 一变就飘。
    现在：5+5 双层椭圆花瓣、只留内阴影勾边、去掉外发光；
    位置改用 `groundPoint()` 把脚底世界坐标投影成屏幕百分比，落在脚底 +5~10%、从脚**前面**长出来；
    生长顺序改成年草叶→花茎→叶子→外瓣→内瓣→花心，才像「长出来」而不是「弹出来」。

### 再往 3D 推一档：不换模型、不需要源文件（同日第二轮）

确认原站没有源文件后（`asset.generator = "Tripo"`，AI 生成、只发 GLB，`.blend/.fbx/.gltf` 全 404），
改成从**现有 GLB 本身**榨质感。原模型全角色只有一张 baseColor 贴图、统一 `roughness 0.9`、
无切线、无顶点色，所以看着偏平；三件事全在 `renderer/cinema.js` 里运行时完成：

| 做法 | 要点 |
| --- | --- |
| 程序化法线贴图 | 颜色贴图降到 384² → 两轮 3×3 盒式模糊 → Sobel 低频梯度，`normalScale 0.26`。**只取布料/头发大起伏**，不放大 JPEG 噪点，所以脸不会脏、不会出现描边 |
| 粗糙度分层贴图 | 按亮度写 G 通道：亮处（白裙/皮肤）0.62 微光泽，暗处（头发）0.94 保持哑光；`roughness = 1.0` 让贴图全权控制 |
| 平滑法线 | 按量化位置合并同位置顶点法线（UV 接缝拆开的顶点重新连上），`blend 0.72`。蛋糕纯只有 5620 顶点，这一步消低模棱角最明显；**不动几何、不重算 UV** |

- 按 `texture.uuid` 缓存，两个角色各生成一次；`colorSpace = NoColorSpace`，`flipY` 与 `wrap` 复制
  baseColor 贴图，否则 glTF 的 UV 约定会让贴图错位。
- **零新增二进制、零启动阻塞**：canvas 生成失败（图片未解码 / tainted）静默退回原材质。
- 跟随托盘「影视级光影」开关：关掉时 `normalMap` / `roughnessMap` 一起移除，`roughness` 回 0.52，
  整组回退到原版，不是只关灯。
- 自检：`__pet.cinemaState()` 看 `detailMaps` / `smoothed`，`__pet.detailInfo()` 看当前材质挂载状态。
- 热导入的自定义 `.glb` 同样会走这套增强（贴图从它自己的 baseColor 派生）。

**天花板说清楚**：这只 Q 版的手藏在蓬蓬裙和长发后面，骨骼表演的上限有限——
`stretch` 已经改成靠「整段脊柱后仰 + 抬头 + 踮脚」演，而不是抬手臂（会穿模且看不见）。
注意原站模型是 Tripo AI 产物，没有可编辑的绑定源文件，
「拿 .blend 回去手工加表情」这条路在这个项目里不成立。

| --- | --- | --- |
| 表情 / 口型要 blendshape | 五官是**画在贴图上的**，几何上没有眼皮/嘴唇，掰顶点没用；但可以用挂在头骨上的薄 3D 贴片，平时整层隐藏，只在眨眼 / 说话那零点几秒显形 | `renderer/express.js` |
| 精细手指要新模型 | 解析 GLB 发现**本来就有 42 根手部骨骼节点**（左右各 5 指 × 4 节 + 手掌），其中 25 根进了 `rig.joints` 可直接驱动，以前只用来做「轻轻收拢」 | 7 套手势 |
| 没源文件就没法加东西 | 上面两条都不碰源文件、不动原几何、不动原贴图，全部叠加在 `updateRig()` 之后 | 零新依赖 |

- **表情 / 口型**：`probeFace()` 自动找「头部高度、法线朝前、最靠前」的顶点框出脸，
  贴片挂在 `head` 骨骼上随转头一起动；眨眼平均 3~5 秒一次、单点她会眨眼看你，
  说话 / 朗读 / 哼歌时嘴按 5~7Hz 音节张合。右键「表情与手势 → 说两句话」可直接点验。
  位置用 303px 窗口截图做过像素级校准（两眼 y≈123px、间距≈24px）；
  贴片材质必须 `toneMapped: false`，否则 ACES 会把肤色洗成白斑。
- **7 套手势**：比心 / 招手 / 数数 / 托腮 / 弹琴 / 摊手 / 握拳加油，
  逐节卷手指、幅度递减，首尾 0.35 秒淡入淡出；隔一阵自己来一个，
  贴边探头、连击、睡觉时不打扰。
- **重建模型默认不贴表情层**：它现在有真骨架了，但脸是 AI 重画的、五官比例和原角色不同，
  实测贴片会落到脸颊上。与其给一张歪脸，不如保持干净；
  留了 `__pet.calibrateFace()` / `__pet.faceHold()` 自行校准。

### 3. 自检与调试

- `__pet.expressState()`：手势当前状态、登记到的手指骨数、脸部探测框、眨眼 / 口型状态。
- `__pet.playGesture(name)` / `__pet.speak(sec)` / `__pet.blink()` / `__pet.calibrateFace(patch)`。
- `PET_FACE_HOLD=1` 把贴片常显用于校准；`PET_TEST_USERDATA=<目录>` 换一个用户目录，
  调试实例不会顶掉桌面上正在跑的那只（单实例锁 / 全局快捷键都不冲突）。
- 验收：`err=null`、`ready:cake` / `ready:rebuilt`、25 根手指骨登记、比心播放中、
  眨眼与口型联动、细节贴图仍挂载、两个模型均无残留贴片。

### 4. 「要加骨架，要真」：真 glTF skin，不是整体 transform 假演

- 上节的静态重建版只靠 `spinner` 整体摇摆，确实不够。这轮写了
  `tools/rig_transfer.py`（纯 Python 标准库、零依赖），把蛋糕纯那份已被验证能跑动画的
  骨架整棵搬到重建网格上，产出 `models/character-rebuilt-rigged.glb`：
  **68 nodes / 1 skin / 47 joints**，27925 个顶点全部带 `JOINTS_0` + `WEIGHTS_0`，
  权重和恒为 `1.0`，`fallback=0`。运行时默认加载这个版本，静态原件留作对照。
- 步骤：把重建模型躺倒顶点的 `Rx(90°)` 烘焙进 `POSITION / NORMAL` →
  按身高归一到蛋糕纯的 y 0~1 空间、再绕 Y 转 +90° 旋进 cake 坐标系 →
  空间哈希（`CELL=0.035`）取最近 4 个蛋糕纯顶点，按距离倒数混合它们的骨骼索引 / 权重，
  取最大的 4 根归一化 → 连同 `node_0` / `Armature` 父链一起复制骨骼节点与
  `inverseBindMatrices`，`skin.joints` 顺序不变所以索引不用重映射。
- ★ **最大的坑是坐标系，不是权重**。第一版只搬 `Hips` 子树并直接挂到 scene 根，
  丢掉了 cake 的 `node_0`（上面带 `Ry(-90°)` 的坐标转换，mesh 和骨骼都在它下面）。
  结果是网格**不撕裂**、看上去只是「AI 生成模型本来就侧着身」，极易误判成美术问题；
  实际是网格 / 骨骼 / 权重三者差 90°，抬手和走路方向整体偏掉。
  修正：cake 的原始 `POSITION` 正面朝 `+X`、重建模型朝 `+Z`，
  先把重建顶点绕 Y 转 `+90°` 旋进 cake 空间（权重查询才对得上），
  再由复制过来的 `node_0` 的 `-90°` 转回屏幕正面 —— 视觉朝向不变，三者同坐标系。
- 判定工具 `tools/inspect_rig.py`：静止时用 `jointWorld × IBM` 对比 `meshWorld`。
  glTF 允许把坐标转换放在共同父节点上，所以正确的指标不是「等不等于单位阵」，
  而是「等不等于 mesh 的世界矩阵」。修正后 cake 与重建版都是 **0.000000**。
- 自检：`__pet.skeletonInfo()` →
  `{bones:47, arms:2, legs:2, head:true, hips:true, skinned:1}`。
  动作验收跑了 idle / walk / swing / wave 四组窗口截图：正面直立、无撕裂破面、
  裙摆腿脚完整、走路方向正确、秋千坐姿正常、挥手气泡正常。
- 仍有的边界：`used joint indices 0~33`，手指骨 34~46 在骨架里但没有顶点绑上去
  （生成模型手部没有可分离的几何），精细手指形变有限；
  表情贴片仍默认关闭，理由同上。
- 打包：`package.json` 的 `build.files` 已列入带骨架 GLB；`tools/` 只随 git 源码分发，
  不进运行时包 —— 这些是生成期工具，桌宠运行不需要 Python。
